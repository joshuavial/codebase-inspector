# Readable schema diagrams

Reviewed 2026-10-16. A schema of roughly 100 tables needs an index and a way to inspect a small neighbourhood. Changing the layout engine alone does not make every column and relationship readable on one screen.

| Tool | Layout and navigation around 100 tables | Column edges | Licence | Size and offline plain-JS fit |
|---|---|---|---|---|
| dbdiagram / DBML | Automatic placement and manual positioning; table groups, detail levels, table search and filtered diagram views reduce the visible set. The hosted layout implementation is not a public library. | Yes, references name source and target fields. | Hosted renderer is proprietary; DBML tooling is Apache-2.0. | No standalone renderer distribution or library byte size. DBML is a parser and format, not a replacement renderer. Cannot vendor the hosted UI into this viewer. [Views](https://docs.dbdiagram.io/diagram-views/), [groups](https://docs.dbdiagram.io/table-groups/), [DBML](https://github.com/holistics/dbml). |
| drawDB | Dagre left-to-right automatic arrangement; separate packing for isolated tables. Manual placement, subject areas and table search support exploration. A full-schema fit still shrinks long tables. | Yes, SVG routes use connected field positions. | AGPL-3.0. | Whole React/Vite application with UI, editor and parsers; no standalone layout-renderer bundle size. Can self-host after building, but cannot drop its UI into plain JS. [Architecture](https://drawdb-io.github.io/docs/how-it-works), [layout source](https://github.com/drawdb-io/drawdb/blob/main/src/utils/autoArrange.js), [package and licence](https://github.com/drawdb-io/drawdb). |
| ChartDB | React Flow canvas with movable cards, areas and a table sidebar. Search and selectively showing tables are useful at this size. Its application owns placement and visibility; React Flow itself is not an automatic layout engine. | Yes, field handles. | AGPL-3.0. | Whole React/TypeScript/Vite application, not a standalone browser library. No comparable single-file renderer size. Offline self-hosting needs a build; direct integration would introduce React and application state. [Source and build](https://github.com/chartdb/chartdb), [dependencies](https://github.com/chartdb/chartdb/blob/main/package.json). |
| Azimutt | Explorer built around finding a table, adding related tables, hiding columns, and saved layouts. This is the strongest interaction model to borrow for large schemas. Manual placement and selective display matter more than whole-schema packing. | Yes. | MIT for the open source repository. | Whole Elm/TypeScript application and supporting packages; no single-file renderer release or comparable byte size. Can self-host a built app; extracting it is a substantial integration even though it does not require React. [Features](https://azimutt.app/features), [source](https://github.com/azimuttapp/azimutt). |
| SchemaSpy | Graphviz-generated overview plus per-table relationship diagrams and searchable HTML documentation. Local diagrams avoid fitting all columns at once. | Yes, Graphviz table ports. | LGPL-3.0. | Java/JDBC generator plus Graphviz, not a browser file. Generated HTML/SVG works offline. Would require another generation path and database metadata rather than reuse our browser projection. [Documentation](https://schemaspy.readthedocs.io/en/latest/), [source](https://github.com/schemaspy/schemaspy). |
| Mermaid erDiagram | Declarative ER layout with direction controls and layout-engine choices. No built-in schema search, neighbour explorer or domain grouping workflow; the viewer would still need to choose a subset. | Relationships attach to entities; PK/FK attribute annotations do not create field-to-field routes. | MIT. | Measured Mermaid 12.2.0 classic minified bundle: 5.49 MB uncompressed. Can vendor and run offline without React or a local build, but larger and less precise than the existing renderer. [ER syntax](https://mermaid.js.org/syntax/entityRelationshipDiagram.html), [layouts](https://mermaid.js.org/config/layouts), [licence](https://github.com/mermaid-js/mermaid/blob/develop/LICENSE). |
| Graphviz / Viz.js | `dot` layered layout, clusters, disconnected-component packing and HTML table labels. Strong static layouts; search, neighbourhood filtering and interaction remain our work. | Yes, named HTML cell ports. | Viz.js MIT; Graphviz EPL-2.0 and bundled component notices. | Measured Viz.js 3.31.0 global distribution: 1.33 MB uncompressed, including its embedded runtime. A vendored global browser script can work offline without React or a local build. Viable, but adds a WASM engine and a DOT-to-SVG integration. [API](https://viz-js.com/api/), [ports](https://graphviz.org/doc/info/shapes.html), [licences](https://github.com/mdaines/viz-js), [Graphviz licence](https://graphviz.org/license/). |
| ELK / elkjs | Layered orthogonal routing, compound groups and fixed column ports. We supply search and a bounded focus view; graph size is then small enough that routing and labels stay readable. | Yes, `FIXED_POS` ports aligned with column rows. | EPL-2.0. | Already vendored. Current upstream 0.12.0 bundled file measures 1.61 MB uncompressed. Works offline as a global script, without React or a build. No additional dependency. [elkjs](https://github.com/kieler/elkjs), [port constraints](https://eclipse.dev/elk/reference/options/org-eclipse-elk-portConstraints.html). |

Sizes are downloaded distribution bytes, not compressed transfer or installed sizes. They were measured from the named versions on unpkg: [Mermaid](https://unpkg.com/mermaid@12.2.0/dist/mermaid.min.js), [Viz.js](https://unpkg.com/@viz-js/viz@3.31.0/dist/viz-global.js), [ELK](https://unpkg.com/elkjs@0.12.0/lib/elk.bundled.js). Application rows have no comparable standalone library artifact; no application build was installed or benchmarked.

Keep ELK and our SVG renderer. Make the overview an index, with connected components and a searchable list at normal text size. Selecting a table opens it with two neighbours per page. Route every visible relationship between column ports, preserving parallel keys and self references. Show key and connected columns first, then a short preview; keep the complete column list in the scrollable details pane. This follows the selective exploration used by Azimutt and SchemaSpy without another dependency or a second rendering stack.
